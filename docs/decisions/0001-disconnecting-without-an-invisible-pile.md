# 0001. Disconnecting without an invisible pile

*2026-09-19. Cited in the code as §10, "Disconnecting without an invisible pile". A `§` here means a section of [`ARCHITECTURE.md`](../ARCHITECTURE.md).*

**A source that is let go must not leave notes where nobody can see them, and must not take unsent work with it unasked.**
It used to do the first (the rows went under `LOCAL_CONNECTION_ID`, shown only when nothing else is connected); since the second change below it does neither (§6, "Letting a source go").
The owner's rule is that a disconnect removes the source's notes from the device — the remote has them — and that what the remote does *not* have is the user's decision: move it to another connected source, download it, discard it by name, or cancel.
Where there is nobody to ask (a credential revoked from another device), the source is detached in place and stays on screen until somebody is.
There is **no migration** for a pile an earlier disconnect left: nothing has been released, so the code that serves such a pile is deleted rather than carried.
- **Plumbing, with nothing the user can see.**
  `store/unsynced.ts` says what a source holds that its remote has not been sent — notes (dirty, never pushed, or with a `write` queued), renames (clean and pushed, a `move` queued), deletes (a tombstone with a `remoteId`; one without owes nothing), notebooks (a `mkdir` queued, or no `remoteId` *and* no fully sent note anywhere beneath: only `createFolder` and `moveFolder` queue a `mkdir`, and a notebook that came into being around a note is made by the engine's `ensureRemoteFolder` on push, which reports no id, so its row has none until a later pull — a sent note inside it is the proof the directory exists), queued `rmdir`s, and whether the queue is `blocked` — for one connection by name, since an id and an op's `noteId` mean nothing outside their source.
  A connection still `resumeUnverified` counts **every** live note and notebook and says `unverified`: its rows look sent, but `verifyResume` has not yet found the files, and a discard that believed the rows would delete the only copy.
  `blocked` is the scheduler's rule and not a second one: `outOfAttempts` and `MAX_OP_ATTEMPTS` moved to `store/queue.ts` and the scheduler reads them from there.
  It is never true of an `rmdir`, because the engine never stops at one: out of attempts, it is completed as done and stepped over (`drainOps`).
  `store/heldEdits.ts` takes over the `beforeClosing` registry from `store/staleTab.ts` and adds `settleEditors()`, because text an editor still holds is in no row and a count taken from the store alone would leave out the last sentence typed; `Autosave.settle` answers with the notes it still holds text for that the store would not take, named by `noteRef` — a count, until the change below had to keep exactly those rows and a number could not say which they were — and a flush that rejects is counted instead, since one that threw can say nothing about which note it was holding.
  **Still per tab, and still across sources:** a settle reaches the editors of this tab alone, and it settles every source they hold text for rather than the one being let go, so "this source has unsaved text" is answered from the refs where there are refs and from the rejection count otherwise, which cannot tell one source from another.
  `syncState.displayName` is written on every reconcile and on bind, and kept by every writer of the row, so a source the server will no longer answer for can still be named.
  `store/exportNotes.ts` is a store-only ZIP written by hand (CRC-32, UTF-8 names, no dependency, and no CSP change: a blob behind `<a download>` is neither a script nor a fetch) of each note as the file a push would send, at its path.
  The name written is the name compared: normalized, relative, never `..`, a backslash made `_` (a separator to some Windows extractors, so otherwise a way out of the folder it is unpacked into), and `untitled.md` where nothing is left; colliding names are numbered, a file that would sit where a folder has to be among them; and it throws rather than write a field that would wrap or mean ZIP64 (65,535 entries, 4 GiB, a name over 65,535 bytes).
  Linear in the number of notes, because it runs on the main thread at the moment the user most needs it to finish.
  It is deliberately *not* the export/import of §14, which stays unplanned: it exists for the one position sync cannot help with — text that is only on this device, in a source that cannot be reached — where "discard or cancel" would otherwise mean the user can never leave without losing it.
  Its first caller is the detached panel's Download, in the change below
- **Every disconnect is a detach in place, and the code that served the pile is gone.**
  `syncState.detached` (`at`, `disconnected` | `revoked` | `interrupted`; unindexed, so no schema version and — nothing being released — no migration), `detachConnection` on every unbind path, `releaseConnection` for the discard, the `activeConnectionId` fallback that prefers a live source, and the scheduler, sync-store, token-source and reconcile guards, as §6 now describes.
  The panel gains Reconnect, Download and the two-step Discard; the disconnect confirm says the notes are removed from the device and how many changes will stay behind; the undo notice says when a note came back into a disconnected source.
  `unbindConnection`, `NOTES_ACCOUNT_KEY`, `MIXED_ACCOUNTS`, `labelFor`, `heldLocally`, `needsAsking`, `adoptAccount`, the `other-account` state and its panel were deleted here rather than in the last change: with no disconnect filling the pile they were unreachable, and dead code that decides where notes go is worse than none.
  `LOCAL_CONNECTION_ID` survives as "nothing has ever been connected", and `bindConnection` still copies its rows into the first source bound.
  Two things found on the way: a save held for a row the detach removed could be matched *by id* to another account's note (`whereShown` now looks by id for the device's own notes only), and "stop syncing on this device" used to leave the credential behind (the connection transaction now covers `credentials`).
  **Review of the first cut (2026-09-19) closed what it had left open, and two ways text was dropped:** a detach marked every removed row as deleted-here, so text an editor still held for one — typed while the server was being asked, or a save that had been failing — was let go on arrival; now nothing a detach removes is marked, such a save makes the note again under its source (`ensureDetached`, with the account this tab remembers for it), the editors are settled immediately before every detach, and `settleEditors` answers with the failing notes' refs so that their rows are kept whatever they say.
  And Discard's `seen` named notes by ref alone, so a note written into after the list was shown went with the list; it now carries each note's `updatedAt`, the notebooks and `rmdir`s by path, and a mismatch is unseen.
  Also: `releaseConnection` refuses a source reconnected meanwhile; a resume into a connection that already holds the file yields to the pulled row (a kept edit becomes a conflict copy); marks in `deletedHere` are per binding (`boundAt`) so a reconnect's pull cannot be mistaken for the delete before it; a re-made source never takes the screen, and the device's own pile is listed and showable when it holds anything; both confirms close on Escape, the discard panel's focus is guarded and handed on when its source goes, and the tombstone warning is said plainly.
  **Left:** the source list names live sources by account id, not by the server's name — the name is written onto a row only when that source is reconciled, which is only while it is in front, so a list naming by it would rename a source the first time it was shown
- **The dialog before a disconnect, and moving unsent notes to another source.**
  The order is the rule: the editors settle, one last push runs where it could work (ten seconds, then the question anyway), what is unsent is read, and the user is *asked* — and nothing is said to the server until they answer, which a test pins by asserting the disconnect mock is untouched while the question is up.
  The four cases are the owner's: nothing unsent is the plain confirm; unsent with somewhere to put it offers Move, Download, Discard and Cancel; unsent with nowhere offers the last three; and offline or blocked adds why, with "cancel and try again later to keep them".
  Each step is asked as every question in the app is ("Dialogs", §7; the owner's rule, 2026-10-15): Cancel first and the answer last, and the focus on the answer — Disconnect, Discard for good and Move them, each drawn as what it is — or, in the full question, which has no one answer, on Cancel, or on the first account to move to where there is a choice.
  The step drawn next takes the focus the same way, since the button that was pressed goes with the step it belonged to and focus left on the page is a user whose Escape reaches nothing.
  Escape is the step's Cancel — a move's second step goes back to the offer, the question itself closes — a failing save in this source disables Move and Discard and points at the note's own banner, and a count per category sits above five titles with the rest in a `<details>`.
  Every number the user sees comes from one rule (`countedFolders`): a notebook is counted only where no unsent note is inside it, so the headline, the breakdown and both steps of a move cannot disagree, and the empty notebook an unsent rename leaves behind is named rather than smuggled across.
  `moveUnsyncedTo` is the only operation in the app that carries writing from one storage account into another, so it names the account (a radio list where there is more than one) and says in a second step exactly what will be in each afterwards — including that a note pushed once ends up in both, and that unsent deletes and renames are not carried because each is about a file only the old account has.
  What it takes and what it leaves is set out in §6.
  It shares the `seen` rule with the discard: read again inside the transaction, and anything written since the list was made is kept rather than moved or let go, with the source detached around it.
  The same Move is on the detached panel.
  It is offered only where it means something — another live source, something movable on the list, and a source whose files have been checked against its remote — and the one confirm in the app that writes into another storage account names that account by the name the server gave it, falling back to the provider's id, rather than by the id the switcher uses.
  A source that is `resumeUnverified` says so in place of the headline, because “n changes have not reached X” is simply false of a list that is the whole library, and points at cancelling and connecting again as the answer.
  **Not done, and why:** the design asked for the editor to be made `inert` from the first settle until the release finishes; the panel does not own the editor, and what that was for is already covered — a keystroke landing while the question is up is kept by `seen` and the source stays around it, which is stronger than a guard one tab can hold
- **The sweep, and this plan.**
  Nothing here is anything the user can see.
  The deletion planned for this change — `MIXED_ACCOUNTS`, `NOTES_ACCOUNT_KEY`, `other-account` and the rest — landed with the detach change above, which is what made them dead, and a sweep for whatever the three changes left after them (a prefs key still read but no longer written, CSS for a panel that no longer exists, an export with no caller, a type with no user, a test helper nothing calls) found none of theirs.
  That is the tooling working rather than luck: `noUnusedLocals` and `noUnusedParameters` fail the build on a declaration the moment its last use goes, so the only dead code a change like this can leave behind is an *export*, and the exports that have none — `heldCredentials`, `useDirtyCount`, and the Phase 1 store functions the tests are the only callers of — all predate this work and are not its to delete.
  (`heldCredentials` and `useDirtyCount` were deleted on 2026-10-26, when knip's report was cleared for #461.)
  What was left was the prose, and §6 and §7 now describe the world these four changes built rather than the one they replaced: in particular `LOCAL_CONNECTION_ID` is described again as what it has always been and nothing more — never connected, or nothing connected — since `bindConnection` copying its rows into the first source bound is the only thing that fills or empties it

**What the four together guarantee, so it need not be assembled from four entries.**
The remote is the source of truth, so letting a source go takes off the device exactly what the remote has and nothing else; connecting the account again brings it back.
What the remote was never sent is never discarded and never moved into another account unless the user says so: Disconnect settles the editors, sends one last push where that could work, reads what is unsent and *asks* — move it to another connected source, download it, discard it by name, or cancel, and on the only source discard, download or cancel — with nothing said to our own server until the answer comes, so a cancel leaves the device as it was and the connection standing.
The last push is the exception, and it is not one really: it finishes what the user had already asked for, and a cancel after it leaves their notes further along than before, never behind.
Where there is nobody to ask, because the server has stopped answering for the credential, the source stays on the device marked `detached`, holding what it was never sent, shown and editable and saying so in the list, until there is somebody.
And no disconnect fills the device's own pile, so what the user has been told is on their device is somewhere they can see it.
**Not done, and why**, each said with the change it belongs to: the editor is not made `inert` while the question is up, since `seen` keeps whatever is typed meanwhile and the panel does not own the editor; `settleEditors` reaches this tab's editors and every source they hold text for, not the one being let go; and §7's directory removal still names the folder by the id the queue recorded, and gives up where it has none.
