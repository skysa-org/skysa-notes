The server is now the shared kit's, `@skysa/server`, installed from npm with the rest; `apps/api` keeps the Worker's entry and its `wrangler.toml`. With the stock entry and `apps/api/wrangler.toml` there is nothing to do beyond the routine steps. A Worker entry of your own that imported from the server's files beside `src/worker.ts` (`./app.js`, `./env.js`, `./http.js`, `./relay/durableObject.js`) imports `createApp`, `parseEnv`, `envWarnings` and `misconfigured` from `./index.js` there, as the stock entry now does, or from `@skysa/api` anywhere else, and `ConnectionRelay` and `durableObjectRelay` from `./relay.js` or `@skysa/api/relay`; one that already imported from `@skysa/api` builds unchanged. A `wrangler.toml` of your own points `migrations_dir` at the server's migrations, which `pnpm install` puts at `apps/api/node_modules/@skysa/server/migrations`, written from wherever your file is: they are the same files under the same names, so a database migrated before applies only the migrations added since, which in this release is `0007_drop_sign_in_tables`. `pnpm db:generate` is gone with the schema it read.
